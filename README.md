# Telegram Gifts NFT Sniper 🎁🤖

Автоматический снайпер и ИИ-аналитик рынка NFT-подарков Telegram (сеть TON).

Бот мониторит рынок, отбирает сделки детерминированным фильтром, сверяет
решение с Claude и соблюдает риск-лимиты и банкролл. Реальная подпись
транзакций **не реализована**, живой режим заблокирован в коде — покупка
пока только симулируется.

## Как это работает

1. **Сбор данных** — TonAPI.io (`/v2/nfts/collections/{address}/items`),
   с фолбэком на Getgems GraphQL. Собираются: адрес подарка, адрес и имя
   коллекции, номер минта, цена продажи (нанотоны → TON).
2. **Честный Floor Price** — у API нет сортировки по цене, поэтому floor
   считается **выборкой**: тянется несколько страниц (по умолчанию 5×100)
   и берётся **5-й перцентиль**, а не `min()`. Перцентиль устойчив к
   «пылевым» лотам, которые утащили бы минимум на дно. Если выборка меньше
   `MIN_FLOOR_SAMPLE`, floor считается недостоверным и торговля пропускается.
3. **Защита от скам-коллекций** — лот проверяется по `COLLECTION_WHITELIST`
   **по адресу контракта**, а не по имени (имя и картинки подделываются
   тривиально). Адреса сравниваются после нормализации, поэтому `EQ...` и
   `0:abc...` формы одного адреса корректно совпадают.
4. **Редкость трейтов** — для Telegram Gifts редкость модели/фона/символа
   влияет на цену **сильнее номера минта**. Частоты трейтов считаются по той
   же выборке, что и floor. Влияет на решение только через оценку
   (`PREMIUM_MULT`), которая по умолчанию нейтральна — см. раздел ниже.
   Важно: «редкость оценить не удалось» (`null`) — это **не** синоним
   «обычный» и **не** синоним «редкий».
5. **Ликвидность** — floor не говорит, *продастся* ли лот. Бот считает
   **конкуренцию у floor**: сколько продавцов уже стоит в полосе
   `COMPETITION_BAND_PCT` вокруг floor. Если их больше `MAX_COMPETITION`,
   ваш undercut встанет в очередь и флип не закроется — сделка отклоняется.
6. **Дедупликация** — один и тот же лот по той же цене не уходит в Claude
   повторно `SEEN_TTL_SEC` секунд. Ключ включает цену и огрублённый floor,
   поэтому реальный сдвиг рынка всё-таки вызывает пересчёт.
7. **Детерминированный фильтр `evaluate_trade()`** — единственный источник
   истины о сделке: прибыль, ROI, конкуренция, ликвидность. Считается **до**
   обращения к Claude, потому что ИИ всё равно не может отменить его отказ —
   спрашивать про отбракованный лот значило бы платить за ответ ни о чём.
8. **ИИ-мозг** — Claude даёт **второе мнение** по лотам, прошедшим фильтр,
   и возвращает строгий JSON `{ ACTION, ROI_PERCENT, NET_PROFIT_TON, REASON }`.
   Купить можно только при согласии обоих.
9. **Риск-лимиты** — последний контур перед тратой денег (см. ниже).
10. **Цикл** — бесконечный `while True` c задержкой 10–15 сек и подробным
    логом каждой проверки и вердикта.
11. **Покупка** — заглушка `execute_blockchain_buy()` симулирует успех
    (`[SUCCESS] ...`) вместо реальной транзакции; позиция пишется в SQLite,
    при настроенном токене уходит уведомление в Telegram.

## Что проверено на живых данных, а что нет

Ответ `tonapi.io` разобран на реальной коллекции (Timeless Books, выборка
50 предметов): `sale.price.value` в нанотонах, `sale.address` (контракт
продажи — именно туда уходит платёж), `sale.market.name`, `collection.address`,
атрибуты и номер минта. Номер минта берётся ТОЛЬКО из `metadata.name`:
верхнеуровневый `index` — огромное отрицательное число, не номер.

Там же закрылся вопрос валюты: **GRAM в интерфейсе Getgems — это нативная
монета TON** (`currency_type: "native"`, `decimals: 9`), поэтому расчёт
в TON/нанотонах верен.

Запасной источник `api.getgems.io` **не верифицирован**, и адрес контракта
продажи он не возвращает вовсе — его лоты годятся для расчёта floor, но не
для покупки.

Отдельно: эндпоинт **истории продаж** не проверен вовсе, поэтому фильтр
ликвидности по сделкам **выключен по умолчанию** (`ENABLE_SALES_HISTORY=0`).
Всегда работающая часть фильтра — конкуренция у floor — считается по данным,
которые бот и так получает, и от этого эндпоинта не зависит.

## Режимы запуска

```bash
python gift_sniper.py --record      # 1. копим запись рынка (не торгует)
python gift_sniper.py --backtest    # 2. прогоняем решения по записи
python gift_sniper.py               # 3. торговля (после того, как п.2 убедил)
```

Бэктест гоняет **ту же функцию `evaluate_trade()`**, что и боевой бот. Это
принципиально: бэктест по отдельной копии логики не проверяет ничего.

Исторического API продаж нет, поэтому бэктест работает по **собственной
записи** рынка: сначала `--record` несколько дней, потом прогон. Позиции, для
которых запись закончилась раньше горизонта удержания, считаются **незакрытыми**
и в winrate не попадают — домысливать за них исход значило бы подогнать результат.

Главная цифра отчёта — **расхождение прогноза и факта**. Если модель обещала
+0.58 TON, а вышло −0.47, торговать пока рано.

## Риск-лимиты

Потолок сделки, часа и суток, лимит открытых позиций и **стоп после N убытков
подряд**. Лимиты живут в SQLite, поэтому **перезапуск их не сбрасывает** —
лимит, который обнуляется рестартом, не лимит.

## Премия за красоту и редкость

`PREMIUM_MULT` = 1.0 по умолчанию. Это значит, что красивый номер и редкие
трейты **не влияют на решение** — они только отображаются в логе.

Так сделано намеренно. Модель оценивает лот по floor коллекции; премия за
редкость — это *предположение* о том, что редкое продаётся дороже, и любое
значение выше 1.0 **увеличивает расчётную прибыль**, то есть двигает бота в
сторону «покупай». Калибруйте её по своей записи рынка (`--record` →
`--backtest`), а не на глаз.

Отдельно: проверки «переплата над floor» в коде нет намеренно — расчёт
прибыли её полностью содержит. Покупка выше floor без премии убыточна
арифметически, поэтому отдельная ветка была недостижима и удалена.

## Экономика сделки

```
SALE     = Floor × (1 − undercut)          # продать РОВНО по floor нельзя
PROCEEDS = SALE − SALE×fee − SALE×royalty  # комиссии с цены ПРОДАЖИ
PROFIT   = PROCEEDS − Buy − gas
```

Отличия от наивной формулы `(Floor − Buy) − Buy×5% − gas`:
комиссия берётся с цены продажи (а не покупки), добавлено роялти создателю,
и учтён undercut. Все три правки смещают оценку в **консервативную** сторону —
наивная формула систематически завышала прибыль.

## ⚠️ Безопасность

- `DRY_RUN=1` (по умолчанию) — покупка только симулируется, средства в
  безопасности.
- Секреты — только через окружение; **приватный ключ кошелька — только через
  файл с правами 0600** (`WALLET_KEY_FILE`), не через переменную: env видно
  в `ps` и в логах. `.env`, `*.db` и `*.key` уже в `.gitignore`.
- **Никогда не присылайте приватный ключ в чат** — ни мне, ни кому-либо.
- Реальная подпись транзакции намеренно не реализована. Подключайте её
  (например, через `tonutils` / `pytoniq`) только после полного тестирования
  и на свой риск.

## Примечание про модель

В ТЗ упоминался `claude-3-5-sonnet` — это устаревший ID. По умолчанию
используется актуальная быстрая и недорогая модель `claude-sonnet-5`
(идеально для частого опроса). Переопределяется переменной `CLAUDE_MODEL`.
